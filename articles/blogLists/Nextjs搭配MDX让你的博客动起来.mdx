## MDX解决的问题
  在MDX出现之前，我们使用markdown来写博客，但是markdown只有静态的表示能力，无法实现一些比较复杂的功能。例如当我们需要在演示交互式图表或者组件效果，
  markdown就无法帮我们实现。而MDX能在 Markdown 格式的内容中插入 JSX 代码， 在演示交互式图表或弹窗，可以直接将它们嵌入到所书写的内容当中。

## MDX 示例
 - [MDX官方示例](https://mdxjs.com/)
 ### 本地示例-直接在markdown中插入组件

```jsx
// xxx.mdx文件
import { RotateAlbum } from "@/components/album";
// 旋转相册
<RotateAlbum/>
```

## 在Nextjs中使用MDX
### 方式一：使用 @next/mdx 插件
  使用 @next/mdx 加配置next.config.js完成整合,这种方式的好处是可以直接导入作为组件，无需手动去解析mdx文件内容，
  Next在背后已经处理了Markdown和React组件到HTML的全过程，具体配置见[官方文档](https://nextjs.org/docs/app/building-your-application/configuring/mdx)
  ```jsx
  import Welcome from '@/markdown/welcome.mdx' // 直接将mdx文件作为组件导入
  export default function Page() {
    return <Welcome />
  }
  ```
你甚至可以为每个mdx文件创建一个以文件路径为路由的访问url，具体配置见[官方文档](https://nextjs.org/docs/app/building-your-application/configuring/mdx#using-file-based-routing)

my-project  
├── app  
│   └── mdx-page  
│       └── page.(mdx/md)  
|── mdx-components.(tsx/js)  
└── package.json  

在浏览器中直接导航到/mdx-page就可以访问到该页面。

但是这种方式仅限于解析本地的mdx(md)文件，无法解析远程的mdx(md)文件。另外元素据的导出只能通过 export metadata = {} 这种方式导出。

如果你的元数据不是通过export导出，你可能需要改成这种方式的方式导出，因为@next/mdx默认不支持提取这种格式的元数据(@next/mdx does **not** support frontmatter by default)，这也是使用 @next/mdx 插件的一个缺点。对于已经拥有大量md文件的项目来说，去手动改造也是有成本的。

### 方式二：使用 next-mdx-remote 插件

  如果你的mdx文件在远程服务器上或者数据库中，next-mdx-remote是更好的选择。


  ```JSX
  import { MDXRemote } from 'next-mdx-remote/rsc'
 
  export default async function RemoteMdxPage() {
    // MDX text - can be from a database, CMS, fetch, anywhere...
    const res = await fetch('https://...')
    const markdown = await res.text()
    // 对markdown做一些特殊处理
    const transformedMarkdown = transform(markdown)
    return <MDXRemote source={transformedMarkdown} />
  }
  ```

  另外你在获取到mdx文件内容之后，可以对内容做一些特殊处理后(比如提取元数据、配置图片CDN地址等)再进行渲染，这种方式拥有更多的灵活性。
